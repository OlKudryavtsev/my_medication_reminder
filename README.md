# Семейная аптечка — v34

## Что изменено в v34

1. Исправлено редактирование курса лекарства в назначении: при изменении периодичности, например с `1 раз в день` на `3 раза в день`, курс пересоздается корректно с нужным количеством приемов.
2. Секция **Распознать назначение** на вкладке **Назначения** скрыта по умолчанию и раскрывается по кнопке. Дизайн секции сделан более аккуратным.
3. Карточки курсов в назначении переработаны:
   - по умолчанию виден только заголовок курса;
   - заголовок содержит препарат и длительность приема;
   - при раскрытии отображаются формат, доза, способ применения, периодичность, шаблон приема, аналоги, расчет потребности и связь с аптечкой.
4. В курс лекарства добавлены поля:
   - формат;
   - способ применения;
   - аналоги из назначения.
5. Вкладка **Расписание** визуально обновлена. Для приемов, привязанных к еде, отображается не техническое время, а `Завтрак`, `Обед`, `Ужин` с шаблоном приема.
6. В редактировании строки расписания снова доступна привязка к назначению.
7. Удаление строки расписания теперь удаляет запись полностью, а не просто скрывает ее, чтобы редактирование группы курсов не оставляло старые дубли.
8. AI-промпт дополнен полями `dosage_form`, `administration_route`, `analogs` для распознавания назначений врача.

## v44 — мультипользовательская модель семей

В v44 бот переведен с жесткой модели `PARENT_CHAT_IDS/CHILD_CHAT_ID` на базовую мультисемейную модель в БД.

### Что добавлено

Новые таблицы:

- `families` — семьи/контуры доступа;
- `family_members` — участники семьи и роли (`owner`, `parent`, `child`, `viewer`);
- `family_invites` — будущие приглашения по токену;
- `notification_settings` — будущие настройки уведомлений по участнику и профилю.

### Миграция текущих данных

При первом старте после деплоя v44 код автоматически:

1. Создает `Семью по умолчанию`.
2. Создает пользователей для текущих `PARENT_CHAT_IDS` и `CHILD_CHAT_ID`, если их еще нет в таблице `users`.
3. Добавляет родителей как `owner/parent` в `family_members`.
4. Добавляет ребенка как `child` и связывает его с детским профилем.
5. Проставляет `family_id` всем существующим профилям, у которых он еще не был указан.
6. Не удаляет и не пересоздает существующие назначения, курсы, расписания, приемы, историю и аптечку.

Факты приема (`dose_events`) не затрагиваются, поэтому выполненные приемы сохраняются.

### Новые пользователи

Пользователь, которого нет в Railway-переменных, теперь не блокируется. При первом открытии Mini App или `/start` ему автоматически создаются:

- пользователь в `users`;
- личная семья;
- личный профиль `Мой профиль`;
- роль `owner` в своей семье.

Это позволяет использовать один и тот же Telegram-бот разным семьям без отдельного Railway-деплоя.

### API

Добавлены базовые API:

- `GET /api/families` — список семей текущего пользователя;
- `PUT /api/families/{family_id}` — переименование семьи для владельца/родителя.

Интерфейс приглашений родителей/детей планируется следующим релизом, таблицы для этого уже созданы.

## v45 — подтверждение доступа администратором

Новые пользователи больше не получают доступ автоматически.

Сценарий:

1. Новый пользователь пишет боту `/start`.
2. Бот создает пользователя со статусом `pending` и отправляет заявку администраторам из `PARENT_CHAT_IDS`.
3. Администратор получает сообщение с кнопками:
   - `✅ Подтвердить`;
   - `🚫 Отклонить`.
4. После подтверждения пользователю создается собственная семья и личный профиль.
5. До подтверждения Mini App и команды, требующие доступа, недоступны.

Существующие данные текущей семьи не удаляются и не мигрируются повторно. Пользователи из `PARENT_CHAT_IDS` и `CHILD_CHAT_ID` сохраняют доступ без подтверждения.

## v48 — исправление дублей семей/профилей и уведомлений

Версия v48 исправляет миграционную проблему v46–v47: если "Семья по умолчанию" была переименована, повторный деплой мог создать новую семью с прежним названием и дополнительные профили. Миграция v48 идемпотентна и не удаляет медицинские данные.

Что делает миграция при старте:
- находит уже переименованную семью по участникам из `PARENT_CHAT_IDS` / `CHILD_CHAT_ID`;
- сливает случайно созданную новую "Семью по умолчанию" в основную семью;
- переносит профили, назначения, расписания, приемы, аптечку и журнал в основную семью;
- деактивирует безопасные дубли профилей (`Ребенок`, лишние личные профили), предварительно перенося их данные в основной профиль;
- не трогает уже выполненные приемы и остатки лекарств.

Также исправлено:
- выбранный профиль теперь сразу обновляется в верхней кнопке профиля;
- список профилей сначала берет активный профиль из сервера, а не устаревший `localStorage`;
- переключатели уведомлений стали визуально различимыми и подсвечиваются при выборе.
